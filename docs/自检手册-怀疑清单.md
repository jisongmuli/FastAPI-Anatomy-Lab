# 自检手册 · 拿到任何陌生项目的 15 分钟体检法

> 这是你未来最常用的文档。师兄丢给你一个仓库、导师发你一个压缩包、组会要你"熟悉一下这个项目"，
> 你就按这份清单走一遍。**15 分钟后你应该能回答：这项目是干什么的、怎么跑、结构如何、有没有测试、风险在哪。**

---

## 第 0 步：心态（30 秒）

- 你不是来"读懂每一行"的，你是来**画出地图**的
- 看不懂某个文件是**正常的**，先看结构，细节等用到再看
- 遇到看不懂的，用 `docs/00-三天速成路线图.md` 第七节的"求救模板"问 AI

---

## 第 1 步：看门面（2 分钟）

```powershell
Get-ChildItem -Force                     # 顶层有哪些文件/目录
Get-Content README.md -TotalCount 60     # 项目自述
Get-Content requirements.txt             # 依赖清单（能看出用了什么技术）
```

**要回答的问题**：
| 问题 | 从哪看 |
|---|---|
| 这是什么项目？ | README 第一段 |
| 用什么技术栈？ | requirements.txt / pyproject.toml（有没有 fastapi、django、pytest、pandas…） |
| 怎么启动？ | README 的"快速开始" / `Makefile` / 脚本 |
| 谁是作者、什么时候的代码？ | git log（`git log --oneline -10`） |

**红旗**：README 是空的或模板默认内容 → 说明项目缺少维护，后面要多靠自己看代码。

---

## 第 2 步：找入口（2 分钟）

```powershell
# FastAPI 项目：找 FastAPI() 出现在哪
Get-ChildItem -Recurse -Include *.py | Select-String -Pattern "FastAPI\(" -List

# Django 项目：找 settings.py 和 manage.py
Get-ChildItem -Recurse -Filter "manage.py"

# 找主程序
Get-ChildItem -Recurse -Include *.py | Select-String -Pattern "__name__ == .__main__." -List
```

**产出**：入口文件路径 + 启动命令。
**FastAPI 项目**顺手看入口里的 `include_router`，你就知道**一共有哪几个业务模块**。

---

## 第 3 步：画目录地图（3 分钟）

```powershell
# 只看目录结构，不列文件（快）
Get-ChildItem -Recurse -Directory | Where-Object { $_.FullName -notmatch "\.venv|__pycache__|\.git" } | Select-Object -ExpandProperty FullName
```

然后对照这份"目录名 → 职责"对照表，给每个目录贴标签：

| 目录名 | 典型职责 |
|---|---|
| `app/` `src/` `core/` | 主代码 |
| `routes/` `api/` `views/` `routers/` | 接口定义（网址 ↔ 函数） |
| `services/` `business/` | 业务逻辑 |
| `repository/` `dao/` `crud/` `db/` | 数据库读写 |
| `models/` `entities/` `orm/` | 数据库表结构 |
| `schemas/` `dto/` `serializers/` | 接口出入参格式 |
| `utils/` `helpers/` `common/` | 工具函数 |
| `tests/` `test/` | 测试 |
| `config/` `settings/` | 配置 |
| `scripts/` `tools/` | 一次性脚本（数据导入、迁移） |
| `docs/` | 文档 |
| `migrations/` `alembic/` | 数据库迁移脚本（**重要**：能看出表结构演进历史） |

---

## 第 4 步：找"接缝"（3 分钟）

**接缝 = 各层之间的调用点**，找到它，你就能把整个项目串起来。

```powershell
# 谁在用依赖注入（FastAPI 的核心接缝）
Get-ChildItem -Recurse -Include *.py | Select-String -Pattern "Depends\(" | Select-Object -First 15

# 数据库连接在哪
Get-ChildItem -Recurse -Include *.py | Select-String -Pattern "create_engine|SessionLocal|sessionmaker|connect\(" | Select-Object -First 10

# 配置从哪来
Get-ChildItem -Recurse -Include *.py | Select-String -Pattern "os.environ|getenv|BaseSettings|\.env" | Select-Object -First 10
```

**产出**：一句话说出"数据从哪来、存到哪去、中间经过谁"。

---

## 第 5 步：跑测试（3 分钟）—— 性价比最高的一步

```powershell
pip install -r requirements.txt
pytest -q                                  # 能跑就先跑一遍
pytest --collect-only -q                   # 只列出有哪些用例（不执行）
pytest --cov=<主包名> --cov-report=term-missing   # 有 pytest-cov 的话
```

**为什么这一步最值钱**：测试文件是**这个项目唯一不会撒谎的文档**。
它会告诉你"作者认为哪些行为重要"。

| 观察 | 说明什么 |
|---|---|
| 完全没有 tests/ 目录 | 项目没测试，改代码风险高 → 你要**先补测试再改** |
| 有测试但大量失败 | 环境不对 / 代码已腐烂 → 先搞清是哪个原因 |
| 测试全过且覆盖率高 | 项目健康，可以放心上手 |
| 只有 1~2 个测试文件 | 覆盖不全，重点逻辑靠你自己验 |
| 测试里有 `time.sleep` | 测试写得不好，会慢且不稳定 |

---

## 第 6 步：跑起来手工点一遍（2 分钟）

```powershell
uvicorn app.main:app --reload      # FastAPI
# 然后打开 http://127.0.0.1:8000/docs
```

**在 `/docs` 上做的事**：
1. 把所有接口**扫一遍**，看 URL 和字段（这就是接口契约）
2. 挑 2~3 个核心接口**真的点一次**
3. 故意传错参数，看错误处理是否友好

**产出一句话**："这个服务提供 X 类接口，核心是 Y。"

---

## 第 7 步：风险扫描（2 分钟）

```powershell
# 硬编码的密钥/密码（安全隐患）
Get-ChildItem -Recurse -Include *.py,*.yml,*.yaml,*.json | Select-String -Pattern "password\s*=\s*[`"']|secret\s*=\s*[`"']|api_key\s*=\s*[`"']" | Select-Object -First 10

# 被吞掉的异常（排障噩梦）
Get-ChildItem -Recurse -Include *.py | Select-String -Pattern "except\s*:\s*$|except Exception:\s*pass" | Select-Object -First 10

# 遗留的待办
Get-ChildItem -Recurse -Include *.py | Select-String -Pattern "TODO|FIXME|HACK|XXX" | Select-Object -First 15

# 调试残留
Get-ChildItem -Recurse -Include *.py | Select-String -Pattern "print\(|breakpoint\(\)|pdb\.set_trace" | Select-Object -First 15
```

| 发现 | 含义与行动 |
|---|---|
| 硬编码密码 | 安全问题，若这项目要上线则必须改；也提示你**别学这个写法** |
| `except: pass` | 出问题查不到原因，属于坏味道 |
| 大量 TODO/FIXME | 作者自己知道哪里没做完，这些是**最好的上手切入点** |
| 散落的 `print` | 调试残留，说明日志规范不统一 |

---

## 第 8 步：产出你的"项目体检报告"（1 分钟）

体检完立刻写下这段（**这就是你组会汇报的底稿**）：

```markdown
## 项目体检报告：<项目名>

**它是什么**：一句话（解决什么问题、给谁用）
**技术栈**：FastAPI 0.141 + SQLAlchemy 2.1 + SQLite + pytest（从 requirements.txt 得到）
**入口**：app/main.py，启动命令 `uvicorn app.main:app --reload`
**结构**：routes → service → repository → models 四层，另有 schemas 管出入参
**接口**：共 7 个，核心是 /api/v1/tasks 的增删改查（从 /docs 得到）
**测试现状**：29 个用例全通过，覆盖率 95%；未覆盖的是启动期连接和 2 处边界规则
**风险点**：① 测试用内存库，真实库行为未验证 ② 无鉴权，任何人可调用
**我的下一步**：先补 PATCH 空请求体与改标题重复这 2 个用例，再尝试跑通真实数据库
```

**这份报告的价值**：
- 它证明你"真的看过"，而不是"看过了"（导师最烦后者）
- 它明确列出了**风险点**和**下一步**，这是研究生该有的姿态
- 它可以直接变成周报

## 附：常用命令速查（PowerShell）

```powershell
# --- 环境 ---
python -m venv .venv                       # 建虚拟环境
.\.venv\Scripts\Activate.ps1               # 激活
python -m pip install -r requirements.txt  # 装依赖
python -m pip list                         # 看装了什么

# --- 运行 ---
uvicorn app.main:app --reload              # 启动 FastAPI（开发）
python main_minimal.py                     # 直接运行脚本

# --- 测试 ---
pytest                                     # 全部
pytest -v                                  # 详细
pytest -x                                  # 首个失败即停
pytest --lf                                # 只重跑上次失败
pytest -k 关键字                            # 按名字筛
pytest -m integration                      # 按标记筛
pytest --cov=app --cov-report=term-missing # 覆盖率

# --- 搜索代码（比 grep 好记）---
Get-ChildItem -Recurse -Include *.py | Select-String -Pattern "要搜的内容"
Get-ChildItem -Recurse -Include *.py | Select-String -Pattern "Depends\(" -List   # -List 只列首个匹配

# --- 调试 ---
python -c "import app.main"                # 只做导入自检（快速验证有没有语法/依赖错误）
```

## 附：卡住时的排查顺序（永远按这个顺序，别乱猜）

```
1. 报错信息最后一行是什么？（Exception 类型 + 消息）
2. 报错文件路径和行号是哪个？→ 打开那个文件的第 N 行
3. 这是"导入错误"(ImportError) 还是"运行错误"？
     导入错误 → 90% 是依赖没装 / 虚拟环境没激活 / 目录不对
     运行错误 → 看堆栈里最深的那一行是"你自己的代码"还是"库的代码"
4. 我的当前目录对吗？（pytest 必须在项目根目录跑）
5. 我的虚拟环境激活了吗？（提示符前有没有 (.venv)）
6. 改成 `--tb=long` 重新跑，把完整堆栈贴给 AI
```
