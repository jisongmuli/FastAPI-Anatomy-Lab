# 三天速成路线图：Python 基础 + FastAPI + 软件测试

> **你的学习目标（务必贴在心里）：**
> 不是"能自己写出来"，而是 **"拿到一个项目，能在 1 小时内说清它的结构、数据怎么流动、怎么测、测没测过。"**
> AI 负责写实现代码，你负责**看懂 + 验收 + 提问**。
>
> 三天总共约 **18~21 小时**（含敲命令、跑测试、看结果）。

---

## 一、三天的总体设计

| 天 | 主题 | 核心产出（做完你能做到什么） | 时长 |
|---|---|---|---|
| **Day 1** | Python 基础：只求看懂 | 能逐行读懂 `02-最小可运行/main_minimal.py`，能回答"这个函数收什么、吐什么" | 5~6h |
| **Day 2** | FastAPI：看懂请求怎么走 | 能画出本项目的目录地图，能对着 `/docs` 说清 7 个接口各自的输入输出、能追一条请求的全链路 | 6~7h |
| **Day 3** | 软件测试：看懂测试报告 | 能跑 pytest、读懂失败信息、会设计用例（正常+异常+边界）、能判断"测够了没有" | 5~6h |

**每天固定的四步节奏**（照做即可，不要自创）：

1. **读讲义**（40 分钟）：`docs/DayN-*.md`
2. **跑起来**（20 分钟）：照着讲义里的命令敲，一定要亲眼看到输出
3. **对照读代码**（2~3 小时）：打开讲义里点名的文件，逐行对注释看
4. **自检 + 提问**（30 分钟）：回答讲义末尾的自检题，答不出的直接问 AI（有提问模板）

---

## 二、明确"不做"清单（这是三天能成功的最大保证）

以下内容**三天内一律不碰**。碰了就会卡住，卡住就会怀疑自己：

| 不做 | 为什么 |
|---|---|
| ✗ 手写算法（排序、递归、动态规划） | 与"看懂后端项目"无关，研究生阶段也不考 |
| ✗ 背语法细节 | 你随时能查，AI 随时能写 |
| ✗ 从零搭建项目脚手架 | 用现成的标本改，比从零搭快 10 倍 |
| ✗ 学 async/await 的底层原理 | 只需知道"这是并发写法，接口 def 前加 async 也行"，会用即可 |
| ✗ 学 Docker / Nginx / K8s 部署 | 组会和个人项目用不到，等真需要再学 |
| ✗ 深入 SQL 优化、索引原理 | 只需看懂"有张表、有几个字段、怎么查" |
| ✗ 学前端 Vue/React | 不是你的任务；FastAPI 自带 `/docs` 就能测接口 |
| ✗ 追求 100% 测试覆盖率 | 覆盖率是参考指标，不是目标 |

## 三、Day 1 详细安排（Python：只求看懂）

| 时段 | 做什么 | 验收标准 |
|---|---|---|
| 第 1 小时 | 读 `docs/Day1-Python基础-只求看懂.md` 第 1~5 节 | 能说出列表和字典的区别，能拆解一个函数的四个部分 |
| 第 2 小时 | 读第 6~8 节 + 在 PyCharm/VSCode 里打开 `02-最小可运行/main_minimal.py` | 能说出每个 `@app.get` 的网址、输入、输出 |
| 第 3 小时 | **启动最小标本**，打开 <http://127.0.0.1:8000/docs>，在网页上点 5 个接口 | 每个接口都返回了结果，知道 `Ctrl+C` 怎么停 |
| 第 4 小时 | 用 `/docs` 故意发错误请求（比如 POST 空 title、GET /users/999） | 亲眼看到 422 和 404 长什么样 |
| 第 5 小时 | 回答 Day1 讲义第 9 节的 7 道自检题 | 至少答对 5 道 |
| 收尾 | 跑一次 `pytest -v` 看到绿色 | 知道"绿色=通过"长什么样 |

**Day 1 过关标志**：你能指着 `main_minimal.py` 的任意一个函数，说出"它收什么参数、返回什么、出错时怎么办"。

## 四、Day 2 详细安排（FastAPI：看懂请求怎么走）

| 时段 | 做什么 | 验收标准 |
|---|---|---|
| 第 1 小时 | 读 `docs/Day2-FastAPI-看懂请求怎么走.md` 第 1~5 节 | 明白"装饰器把网址绑到函数"这件事 |
| 第 2 小时 | **启动主项目** `uvicorn app.main:app --reload`，打开 `/docs` | 看到 7 个接口分组显示 |
| 第 3 小时 | 按 README 的"目录即地图"逐个打开 app/ 下的文件 | 能说出每个文件"一句话职责" |
| 第 4 小时 | 追一条请求：在 `POST /tasks` 上从 routes→service→repository→models 走一遍 | 能画出请求流转图（README 第四节） |
| 第 5 小时 | 在 `/docs` 上把 7 个接口全部点一遍（含改 PATCH、删 DELETE、标记完成） | 每个接口都能说清输入输出 |
| 第 6 小时 | 做 Day2 讲义第 7 节的"绿灯练习"（故意改错代码看会怎样） | 至少做 3 个，看到不同错误码 |
| 收尾 | 回答 Day2 自检题 | 至少答对 8 道（共 12 道） |

**Day 2 过关标志**：给你一个陌生人写的 FastAPI 项目，你能在 20 分钟内说出：入口在哪、有哪几层、每个接口走哪条链路。

## 五、Day 3 详细安排（软件测试：看懂测试报告）

| 时段 | 做什么 | 验收标准 |
|---|---|---|
| 第 1 小时 | 读 `docs/Day3-软件测试-看懂测试报告.md` 第 1~4 节 | 明白单元测试和集成测试的区别 |
| 第 2 小时 | 跑 `pytest tests/演示-失败的测试.py -v`，逐个读失败信息 | 能说出"哪一行、实际什么、期望什么" |
| 第 3 小时 | 读 `tests/conftest.py`，理解 fixture 的作用 | 能解释"为什么要用内存数据库" |
| 第 4 小时 | 读 3 个测试文件，统计每个文件测了什么 | 能说出每个用例的 Arrange-Act-Assert 三段 |
| 第 5 小时 | 跑 `pytest --cov=app --cov-report=term-missing` | 能指出"哪几行没被测到、为什么可以接受" |
| 第 6 小时 | 做 Day3 讲义第 7 节的练习：给"新建任务"功能列出你自己的用例清单 | 至少写出 8 条用例（正常 2 条 + 异常 4 条 + 边界 2 条） |
| 收尾 | 用"测试提问模板"让 AI 帮你生成测试，然后你逐条审查 | 能指出 AI 写的测试里哪条是废话、哪条有价值 |

**Day 3 过关标志**：拿到任何一份 pytest 报告或 Bug 反馈，你能读懂并判断"这个功能到底测够了没有"。

## 六、满三天后你具备的能力（可以写进周报的句子）

- 能独立运行并读懂一个 FastAPI 后端项目的目录结构与分层职责
- 能借助 `/docs`（Swagger UI）手工验证每一个接口的输入输出与状态码
- 能读懂 pytest 测试报告，区分"用例失败"与"服务/数据库故障"
- 能针对一个功能点独立设计测试用例（正常路径 / 异常路径 / 边界值）
- 能向 AI 精确提问："这个模块的工作原理是什么、它的输入输出契约是什么、该怎么测"

## 七、卡住时的求救模板（直接复制改）

### 场景 1：命令报错
```
我在 Windows PowerShell 里执行了：
    <完整命令>
出现的报错是：
    <完整报错文本，不要只截一行>
我的环境是：Python 3.14.2，虚拟环境已激活，当前目录是 <路径>
请告诉我：这个报错的根本原因是什么、我应该执行什么命令、以及我怎么确认问题解决了。
```

### 场景 2：看不懂代码
```
我在读 <文件路径>，读到第 X 行卡住了：
    <贴出这 10 行代码>
请只回答四点，不要重写代码：
1) 这几行在整个请求流程里处于什么位置
2) 每一行在做什么（用一句话）
3) 里面出现的每个函数/变量是什么类型、从哪来
4) 我最可能不懂的 2 个概念，各用两句话解释
```

### 场景 3：不知道怎么测
```
功能描述：<比如"新建任务接口，标题不能重复">
接口：POST /api/v1/tasks
请帮我列出测试用例清单，要求：
- 分三类：正常路径 / 异常路径 / 边界值
- 每条用例写清：准备什么数据、发送什么请求、期望什么状态码和响应
- 不要写代码，只要用例清单，我要自己判断合不合理
```

### 场景 4：让 AI 写测试，你当审查员
```
请为 <文件路径> 里的 <函数名> 写 pytest 测试，要求：
- 用 tests/conftest.py 里已有的 fixture（client / db_session）
- 每个用例写一行中文文档字符串说明它验证哪条规则
- 覆盖：正常路径、异常路径、边界值
写完后请额外列出："哪 2 条用例是价值最高的、为什么"。
```
**关键**：AI 写完你不要直接跑，先问自己"如果这条断言失败了，说明什么坏了？"——答不上来的用例就是废用例。

## 八、三天之后（第四天开始做什么）

1. **把标本换成真项目**：拿实验室/师兄的代码，用 `docs/自检手册-怀疑清单.md` 的 15 分钟体检流程走一遍
2. **给真项目补 3 个测试**：先给最核心的一个函数补，跑通就行
3. **接一个小任务**：让 AI 写实现，你自己写测试、自己跑、自己判断
4. **进入研究正轨**：你的方向偏软件测试，所以接下来该补的是"测试用例设计方法"（等价类、边界值、判定表）和"自动化测试工具"（pytest 进阶、Selenium/Playwright、接口自动化）
