## 一、Python 与工程基础

| 英文 | 中文 | 一句话解释 |
|---|---|---|
| **module** | 模块 | 一个 `.py` 文件 |
| **package** | 包 | 装着多个模块的目录（通常有 `__init__.py`） |
| **import** | 导入 | 从别的文件拿东西来用 |
| **virtual environment / venv** | 虚拟环境 | 项目专属的依赖小盒子，避免版本冲突 |
| **dependency** | 依赖 | 你的项目用到的第三方库 |
| **requirements.txt** | 依赖清单 | 记录需要哪些库和版本范围 |
| **type hint / annotation** | 类型提示 | `name: str` 这种给人看的说明（FastAPI 里是功能） |
| **decorator** | 装饰器 | `@xxx`，给函数贴标签/登记 |
| **class / instance / attribute / method** | 类/实例/属性/方法 | 模板 / 造出来的对象 / 对象的字段 / 对象的函数 |
| **inheritance** | 继承 | `class A(B)`，A 白拿 B 的能力 |
| **exception / raise / traceback** | 异常/抛出/堆栈 | 出错了 / 主动报错 / 报错时的调用链 |
| **refactor** | 重构 | 改结构不改行为（改完测试必须还是绿的） |
| **logging** | 日志 | 比 `print` 正规的记录方式 |

## 二、Web 与后端

| 英文 | 中文 | 一句话解释 |
|---|---|---|
| **client / server** | 客户端/服务端 | 发起请求的一方 / 提供服务的一方 |
| **HTTP method** | HTTP 方法 | GET 读 / POST 建 / PUT 整体改 / PATCH 局部改 / DELETE 删 |
| **endpoint** | 端点/接口 | 一个具体的"网址 + 方法"，例如 `POST /api/v1/tasks` |
| **route / router** | 路由 | 网址到函数的映射 / 一组路由的集合 |
| **path parameter** | 路径参数 | 写在网址里的变量，如 `/tasks/{id}` |
| **query parameter** | 查询参数 | 网址 `?` 后面的，如 `?limit=10` |
| **request body / payload** | 请求体 | POST/PATCH 提交的 JSON 数据 |
| **response** | 响应 | 服务端返回的状态码 + 数据 |
| **status code** | 状态码 | 200/201/204/404/409/422/500 等 |
| **serialization / deserialization** | 序列化/反序列化 | 对象→JSON / JSON→对象 |
| **API** | 应用编程接口 | 程序之间约定的调用方式 |
| **REST / RESTful** | REST 风格 | 用 GET/POST/PATCH/DELETE 表达增删改查的约定 |
| **CRUD** | 增删改查 | Create / Read / Update / Delete |
| **OpenAPI / Swagger** | 接口契约 | 自动生成的接口说明；Swagger UI 就是 `/docs` 那页 |
| **middleware** | 中间件 | 在请求前后统一加工的层（日志、鉴权、CORS） |
| **CORS** | 跨域资源共享 | 浏览器安全策略；前端调后端常被它挡住 |
| **authentication / authorization** | 认证/授权 | 你是谁 / 你能干什么 |
| **token / JWT** | 令牌 | 登录后拿到的凭证，请求时带上 |
| **pagination** | 分页 | `limit` + `offset`，避免一次返回十万条 |
| **idempotent** | 幂等 | 同一操作重复执行，结果一致 |
| **concurrency / async** | 并发/异步 | 同时处理多件事；`async/await` 是它的写法 |
| **deployment** | 部署 | 把服务放到服务器上跑起来 |

## 三、数据库与数据层

| 英文 | 中文 | 一句话解释 |
|---|---|---|
| **database / DB** | 数据库 | 存数据的地方 |
| **table / row / column / field** | 表/行/列/字段 | 数据的二维结构 |
| **primary key** | 主键 | 唯一标识一行的字段（如 id） |
| **index** | 索引 | 加速查询的结构（像书的目录） |
| **SQL** | 结构化查询语言 | 对数据库说话的语言 |
| **ORM** | 对象关系映射 | 用 Python 类描述表，不用手写 SQL |
| **entity / model** | 实体/模型 | 描述一张表的类 |
| **schema** | 模式/结构 | 数据的结构定义；在 FastAPI 项目里常指接口出入参模型 |
| **migration** | 迁移 | 可追溯的建表/改表脚本（Alembic） |
| **transaction / commit / rollback** | 事务/提交/回滚 | 一组要么全成功要么全撤销的操作；确认写入；撤销 |
| **session** | 会话 | 一次数据库对话（不要和"登录会话"混） |
| **query** | 查询 | 向数据库取数据 |
| **JOIN** | 连接查询 | 把多张表按关联字段拼起来 |
| **N+1 problem** | N+1 问题 | 循环里查库导致查询次数爆炸 |

## 四、测试（你的研究方向，重点看）

| 英文 | 中文 | 一句话解释 |
|---|---|---|
| **unit test** | 单元测试 | 只测一个函数/类，不依赖外部环境 |
| **integration test** | 集成测试 | 多个组件一起测（本项目指走完整 HTTP 链路） |
| **end-to-end test (E2E)** | 端到端测试 | 从界面一路测到数据库 |
| **smoke test** | 冒烟测试 | 只验证服务能不能起来、基础接口通不通 |
| **regression test** | 回归测试 | 改代码后再跑一遍，确认没弄坏旧功能 |
| **fixture** | 夹具 | 用例的"统一开局"：准备环境 + 清理现场 |
| **assertion** | 断言 | 说清"我期望什么"，不成立就失败 |
| **test case** | 测试用例 | 一组输入 + 期望输出的描述 |
| **test suite** | 测试套件 | 一堆用例的集合 |
| **coverage** | 覆盖率 | 多少代码被执行过（**不等于验证过**） |
| **mocking / stub** | 打桩/模拟 | 用假对象替换真实依赖（如假的支付接口） |
| **parametrize** | 参数化 | 一份测试逻辑跑多组数据 |
| **flaky test** | 不稳定用例 | 时好时坏的测试（通常是并发/时间/顺序问题） |
| **equivalence partitioning** | 等价类划分 | 把输入分类，每类测一个代表 |
| **boundary value analysis** | 边界值分析 | 重点测边界及边界两侧 |
| **defect / bug / fault / failure** | 缺陷/故障/失效 | 人为错误 → 代码缺陷 → 运行失效（三个层次不同） |
| **test oracle** | 测试预言 | 判断"结果对不对"的依据 |
| **mutation testing** | 变异测试 | 故意改坏代码，看测试能不能发现（**可以发论文**） |
| **TDD** | 测试驱动开发 | 先写测试再写实现 |
| **CI / CD** | 持续集成/持续交付 | 每次提交自动跑测试并部署 |

## 五、研究/论文里高频出现的词

| 英文 | 中文 | 说明 |
|---|---|---|
| **baseline** | 基线 | 用来对比的标准方法 |
| **ablation study** | 消融实验 | 逐个去掉模块看效果变化 |
| **SOTA (state-of-the-art)** | 当前最优 | 论文里常写 "outperforms SOTA" |
| **benchmark / dataset** | 基准/数据集 | 评测用的标准数据 |
| **metric** | 指标 | 准确率、召回率、F1、耗时等 |
| **reproducibility** | 可复现性 | 别人能跑出你的结果（软件工程研究的硬要求） |
| **empirical study** | 实证研究 | 基于真实数据/项目的观察性研究（测试方向主流方法） |
| **RQ (research question)** | 研究问题 | 论文开头的 "RQ1: ..." |
| **threat to validity** | 效度威胁 | 论文里必写的"我的结论可能哪里不成立" |
| **related work** | 相关工作 | 论文第二节 |
| **novelty** | 创新点 | 审稿人最先看的东西 |

## 六、附：三个最容易搞混的"近义词对"

| 容易混 | 区别一句话 |
|---|---|
| **参数 (parameter) vs 实参 (argument)** | parameter 是函数定义里写的名字；argument 是调用时真正传进去的值 |
| **`models.py` vs `schemas.py`** | 前者=数据库表；后者=接口出入参。表里有、接口不给的字段（如密码）就靠它们分开 |
| **覆盖率 vs 测试有效性** | 覆盖率=代码被执行过的比例；有效性=有没有真的验证行为。**100% 覆盖也可能什么都没测到** |
